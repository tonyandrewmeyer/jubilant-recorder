# Staging-repo reference cleanup — 2026-09-03

This project was lifted out of a private staging repo
(`tonyandrewmeyer/canonical-work-queue`). The working tree was full of
pointers to planning documents that only ever existed there — `PLAN.md`,
`STEP3.md`, `STEP9.md`, `STEP7-RPC-ADDUNITS-PLACEMENT-RESULTS.md`,
`STEP7-FOLLOWONS-RESULTS.md`, `BUCKET2-EMPTY-DESIGN.md`, `CLI-CORPUS.md`,
`CMR-FACADE-RECON.md`, `LIBJUJU-CORPUS-AUDIT-2026-07-20.md`,
`PRIOR-ART.md`, `STOP-THE-DRIFT.md`, plus assorted `§`-numbered sections,
"open question N" and "F1"/"F3"/"F5"-style finding labels inside those
missing documents — and three places that named the staging repo outright
(one of them with the wrong org, `canonical/canonical-work-queue` instead
of `tonyandrewmeyer/canonical-work-queue`).

This sweep removed all of it from the working tree. Git history is
untouched, as requested.

## Scope found

**40 files** touched, **266 insertions / 298 deletions**. The initial
estimate was ~91 references across 35 files; the actual count ran higher
once the sweep turned up two categories that weren't in the original
tally (see "Extra findings" below) — a large embedded design narrative
around a fictional dependency, and three stale git-commit citations.

## Treatment breakdown

- **Rewritten to be self-contained** (the large majority): load-bearing
  "why" comments and docstrings where the citation carried no information
  the surrounding text didn't already state, or where the real reasoning
  needed to be written out because it wasn't stated elsewhere. Examples:
  `quiet_window.py`'s "WHY (PLAN.md open question 7)" and
  `preamble.py`'s "WHY the non-empty-model comment (PLAN.md open question
  3)" — both cited from the task brief — plus most of
  `extensions/libjuju/correlate.py`, `cli_translate.py`'s module
  docstring and `§4.x`/`§5.x` section markers, `ai_polish.py`,
  `tagger/llm.py`, `unrepresentable.py`, and a large block of test
  docstrings that cited `CLI-CORPUS.md`, `CMR-FACADE-RECON.md`, or
  `LIBJUJU-CORPUS-AUDIT-2026-07-20.md` for reasoning that was already
  spelled out in the same paragraph.
- **Repointed** to an equivalent that actually exists in this repo:
  `SECRETS-GAPS.md` now points at `correlate.py`'s own comment instead of
  the missing `BUCKET2-EMPTY-DESIGN.md`; `examples/step3_live.py` points
  at `SCHEMA.md`'s "stable key ordering" note instead of "PLAN.md step 2";
  a `test_source_overlay.py` docstring points at `source_overlay.py`'s own
  "decorative, not load-bearing" contract instead of `PLAN.md`.
- **Deleted outright**: bare pointers that added nothing without the
  missing document, e.g. `examples/step9_session2_live.py`'s "STEP9.md or
  a future step-9 writeup will commit it as a fixture", and
  `extensions/libjuju/examples/live/README.md`'s "Closes … the Step 4
  tracking sheet" sentence.
- **Generalised**: numbering that was purely an index into an invisible
  document — `PLAN.md §(C)`, `§4.1`–`§4.12`, `§5.3`/`§5.5`, `Open Q#4`/`Q#5`,
  `F1`/`F3`/`F5` finding labels, "step 7"/"step 10" as bare citations —
  replaced with a plain description of what the thing actually is (e.g.
  `# §4.1 deploy` → `# deploy`; SCHEMA.md's "Plan deltas" section became
  "Design notes" stating the decisions directly instead of diffing them
  against the invisible plan).
- **The `docs/ci-template/README.md` misattribution**: the sentence naming
  `canonical/canonical-work-queue` (wrong org — the repo the task cited is
  `tonyandrewmeyer/canonical-work-queue`) is gone along with the citation;
  the README now just states the plain fact (these are inactive workflow
  templates) without naming any repo.

## Extra findings (beyond the original 91/35 estimate)

- **A leaked sibling-project dependency, `explain-my-model`.** `SCHEMA.md`
  had a substantial design narrative — a full "Alignment with
  `explain-my-model/SCHEMA.md`" section, a "Coupling points" subsection,
  a rejected-alternatives table row, and a version-independence bullet —
  describing the recorder as depending on an external
  `explain-my-model` extractor for model snapshots. The actual code
  (`recording_juju.py::_take_snapshot`) just calls `juju status --format
  json` and parses it with jubilant's own `Status` class; there is no such
  extractor anywhere in the codebase or `pyproject.toml`. Rewrote all of
  it (7 sites) to describe the real data source (`jubilant.Status`) with
  real field names, verified against the installed `jubilant` package.
- **A leaked sibling-project name, `charm-runtime-monitor`**, cited twice
  in `SCHEMA.md` as a comparison point for the JSONL-vs-single-file and
  fixture-format decisions. Generalised both to describe the property
  ("streaming telemetry that needs incremental ingestion") without naming
  the tool.
- **Two broken self-citations**, not references to the missing repo but
  to sections that don't exist in *this* repo's own `SCHEMA.md` either:
  `redaction.py` cited "SCHEMA.md §Redaction" (no such heading exists) and
  `tagger/engine.py` cited "SCHEMA.md §B documents that…" (SCHEMA.md never
  discusses tagger conservatism at all). Both were dangling in the same
  way as a `PLAN.md` citation, just less obviously — dropped the false
  citations and kept the reasoning, which was already fully stated inline.
- **Three stale git-commit SHAs.** `SHELL-HOOK-IMPL-STATUS.md`'s commit
  table cited `373f4b9`/`c296d2d`/`b5f8c59`, none of which exist in this
  repo's history — leftover hashes from the staging repo, presumably
  changed when the commits were replayed into this repo. The commit
  messages matched real commits here (`90d50b1`, `393219d`, `aa7a7a7`), so
  the table now cites the real hashes rather than being deleted.
- **One stale (not dangling-reference) docstring fixed in passing**:
  `extensions/libjuju/tests/test_codegen_smoke.py`'s
  `test_codegen_renders_find_application_offers` docstring said
  `FindApplicationOffers` was bucket-2 and should render as a `# TODO`
  shell stub — it was promoted to bucket-1 with a real `find_offers`
  emitter on 2026-08-18 and the test itself already asserts that. Fixed
  since I was editing the same lines to drop the `CMR-FACADE-RECON.md`
  citation anyway.
